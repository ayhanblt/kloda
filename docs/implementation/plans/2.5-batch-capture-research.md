### Dar dış doğrulama — scratch Xcode proje üretimi

Luna aynı destek sohbetinde ayrı, repo erişimsiz API sorusunu araştırdı.
Context7 üç çağrıda Ruby gem yerine Tuist Swift XcodeProj döndürdü; uygun ID ile
Ruby API doğrulanamadı. RubyDocs 521; açıkça resmî GitHub 1.28.1 tag kaynağına geçildi.
Model `openai/gpt-6-luna`; katalog active doğrulandı. Süre/token/cache UNKNOWN,
tasarruf iddiası yok. Ana ajan aşağıdaki üç kaynağın ilgili paragraflarını HTTP200
ile bağımsız doğruladı; build/runtime sonucu olarak sunulmaz.

| İddia | Resmî kaynak / doğrudan kısa kanıt |
|---|---|
| Target build_settings + save | [README 1.28.1](https://github.com/CocoaPods/Xcodeproj/blob/1.28.1/README.md): `target.build_configurations.each`, `config.build_settings['MY_CUSTOM_FLAG']`, `project.save` |
| Farklı scratch path'e save | [project.rb](https://github.com/CocoaPods/Xcodeproj/blob/1.28.1/lib/xcodeproj/project.rb): `def save(save_path = nil)`; `file = File.join(save_path, 'project.pbxproj')` |
| Extension build file'ını embed fazından çıkarma | [build_phase.rb](https://github.com/CocoaPods/Xcodeproj/blob/1.28.1/lib/xcodeproj/project/object/build_phase.rb): `def remove_build_file(build_file)`; `build_file.remove_from_project` |

Luna aynı build sorusuna tek dar tamamlamada Apple
[Enable Debug Dylib Support](https://developer.apple.com/documentation/xcode/build-settings-reference#Enable-Debug-Dylib-Support)
metnini buldu: “If enabled … main binary code in a separate ‘NAME.debug.dylib’.”
Ana ajan resmî DocC JSON'undaki paragrafı HTTP200 ile doğruladı. `NO` ayrı debug
dylib düzenini kapatır; bu metin entitlement section'larının korunmasını garanti
etmez. Sözleşmede main-executable XML/DER readback bu yüzden bağımsız zorunlu kapıdır.
